## SECTOR MAPPING

### METADATA SECTOR

Return synthesized immutable metadata bytes.

### GAME DATA SECTOR

Read the exact mapped byte range from the source WBFS file.

### FREE SECTOR

Return deterministic zero-filled bytes.

### OUT OF RANGE

Return an I/O error.

### WRITES

Reject writes, trims, discards, resize, and write-zero requests.

## FAT32 LARGE FILE HANDLING

When a source WBFS file exceeds FAT32's per-file limit, expose virtual GAMEID.wbfs, GAMEID.wbf1, GAMEID.wbf2, and later segments. Map each virtual segment to the appropriate byte range in the original source file. Do not physically split or duplicate the source file. Verify the exact boundaries and naming against USB Loader GX through tests.

## STABILITY

- Reported capacity cannot change during an active session.
- MBR, FAT, directory entries, filenames, and cluster chains cannot change.
- Catalog switching requires USB detach, NBD disconnect, validation, and reattach.

# TESTING

## CONTENT POLICY

Use synthetic fixtures and user-supplied legal private WBFS files only. Never download or commit copyrighted game content.

## UNIT

- WBFS validation and game-ID parsing
- Split-set validation
- FAT32 boot sector, FAT, directory, and long-name generation
- Virtual split-file mapping
- Sector-to-source extent mapping
- Unaligned and out-of-range reads
- Snapshot determinism and source identity checks
- Cache isolation and eviction
- Authentication, path safety, and secret redaction

## REFERENCE EQUIVALENCE

For small synthetic fixtures, create a conventional reference FAT32 image and compare the synthesized virtual disk sector by sector.

## INTEGRATION

- Start nbdkit with the custom plugin.
- Connect using libnbd and Linux nbd-client.
- Read and mount the virtual FAT32 partition read-only.
- List /wbfs and compare virtual game ranges with source bytes.
- Prove write, trim, discard, and resize requests fail.
- Reject plaintext and invalid credentials.
- Test server restart, source mutation, catalog switch, and cache limits.
- Test at least 1,000 synthetic entries.
- Test source files requiring virtual FAT32 splitting.
- Validate the TrueNAS Compose file with an independent Compose parser.
- Test the container with the library bind-mounted read-only and all application datasets persistent.
- Prove container restart and replacement preserve metadata.
- Prove the app cannot modify source WBFS files.
- Prove the container does not require privileged mode, Docker socket access, or host block devices.

- Test gadget state-machine behavior without requiring a physical USB Device Controller.
- Verify that write, trim, discard, resize, and write-zero operations are rejected.
- Verify that the Pi services refuse attachment when NBD is unhealthy or the selected export is invalid.
- Use QEMU, chroot, systemd unit verification, and architecture inspection where technically possible.
- Do not require physical USB enumeration.
